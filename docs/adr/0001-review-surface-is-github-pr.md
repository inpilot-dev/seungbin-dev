# 검수 표면은 GitHub PR이다 — 원고 1건 = PR 1개, 승인 = merge

사람이 정해진 시간(일 20:00 슬롯)에 승인·반려·변경·주제변경만 하는 파이프라인에서 "사람이 들어가는 곳"을 정해야 했다.
후보는 셋이었다: n8n + Telegram 버튼(9/14 계획, 이 Mac 로컬 Docker), inpilot.dev/review 웹 인박스, GitHub PR.
GitHub PR로 정했다 — PR은 이미 감사 기록이고, merge가 곧 발행 트리거라 새 인프라가 0이며, 사람의 merge·댓글·push는
GITHUB_TOKEN이 만든 PR 위에서도 워크플로를 깨운다(봇 자신의 이벤트만 안 깨운다). n8n 로컬 Docker는 Mac이 꺼지면
발행이 멈춰 "사람이 터치하지 않는다"와 어긋나고, 웹 인박스는 DB·인증·UI로 2~3주짜리다.

## Consequences
- 원고의 상태는 PR의 상태다: 열림 = 검수 대기, merge = 승인(발행 대기), close = 반려(사유는 댓글), 라벨 `보류`.
- 결정이 없는 원고는 나가지 않는다(보류). 자동 발행 기본값은 없다 — 9/15의 "채점기가 임시 게이트"를 뒤집는다.
- 변경·주제변경은 PR 댓글 명령(`/변경 <지시>`, `/주제 N|<주제>`)이고, 기계가 재생성·재채점해 같은 PR에 밀어 넣는다.
- 폰 한 탭이 필요해지면(10/18 판정) Telegram 버튼을 Vercel 라우트로 얹는다. n8n은 쓰지 않는다 — PR #20은 닫았다.
