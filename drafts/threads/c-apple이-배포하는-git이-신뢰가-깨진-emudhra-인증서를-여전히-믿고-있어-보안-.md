macOS 27.2 업데이트는 문제를 고친 게 아니라 사용자가 손으로 막아둔 우회책을 되돌렸다.

Apple은 17일에 eMudhra 사고를 통보받았다. 28일 기준으로도 macOS에 딸려 오는 git, curl, python3는 신뢰가 깨진 eMudhra 인증서를 여전히 믿는다. 26일에 나온 27.2는 이걸 고치지 않았다. 오히려 직접 적용해 둔 우회책까지 지워 다시 취약하게 만들었다. 그사이 다른 프로젝트 수십 개는 며칠 전에 이미 패치를 냈다. 상당수는 자원봉사자가 운영하는 곳이다.

이 도구들이 여는 HTTPS 연결은 누구든 가로챌 수 있다. git이라면 https:// 원격에서 clone이나 pull을 할 때 공격자가 고른 코드가 들어올 수 있다. push는 전송 중에 바뀔 수 있고 GitHub 토큰 같은 자격증명도 넘어갈 수 있다.
---
확인은 한 줄이면 된다.

git ls-remote https://git-emudhra.we-have-a-problem.com/check.git

인증서 오류가 나면 안전하다. 커밋이 나열되면 영향받는 상태다.

Apple은 Safari와 자사 네트워킹 프레임워크 위에서 도는 앱은 이미 막았다. 남은 구멍은 개발자 도구다. 영향받는 루트 인증서는 손으로 지울 수 있다. 다만 Apple 가이드에 따르면 macOS 업데이트가 이 수정을 되돌릴 수 있다. Apple이 고치기 전까지는 업데이트할 때마다 다시 점검하고 우회책도 다시 적용해야 한다.

CI나 빌드 인프라에서 macOS 러너를 쓴다면 공급망 위험부터 따져야 한다. 업데이트 한 번에 방어가 사라지는 구조다.
