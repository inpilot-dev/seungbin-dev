인증 없이 뚫리는 X 크롤링 경로는 200을 반환한다. 그런데 그 200이 최신 데이터라는 뜻은 아니다.

syndication.twitter.com은 인증 없이 트윗 100건을 준다. 계정별로 실측하니 정체가 다르다. @OpenAI는 20건에 최신 0일 전, 7일 이내 13건. @karpathy는 100건을 채워 주는데 가장 최근이 287일 전, 7일 이내는 0건. @ylecun도 101건에 최신이 286일 전이다.

이 엔드포인트는 최신순 타임라인이 아니라 인기순으로 골라낸 과거 트윗 묶음이다. 날짜 필터 없이 파이프라인에 그대로 넣으면 몇 년 전 트윗이 오늘 다이제스트에 실린다.
---
레이트리밋도 처음 잰 것보다 가혹했다. 초기엔 2~3회 후 분 단위로 풀리는 줄 알았는데, 검증 중 약 25콜을 쓰고 13분 쿨다운을 넘겨도 429가 풀리지 않았다. IP당 연속 2~3회 성공 후 429가 뜨는 것도 그대로다. 하루 1회 배치 기준으로 이 경로가 감당하는 건 핸들 3~5개가 상한이다.

공식 X API v2는 종량제다. 읽기 $0.005/건, 본인 데이터 $0.001/건, 월 300만 읽기. 2026년 2월 Free 티어가 폐지돼 무료 공식 경로 자체가 없다. syndication은 공짜지만 최신성이 없고 429에 취약하고, 공식 API는 최신성이 보장되지만 건당 과금이다. 무료가 아니라 유료를 택하는 순간 최신성과 신뢰성을 사는 셈이다.
---
결론은 syndication을 안 쓰는 게 아니라 폴백 순서를 정하는 거다. 나는 X_BEARER_TOKEN이 있으면 API v2로, 없으면 syndication에 날짜 필터를 강제로 걸고 Bluesky로 보완하는 조건부 폴백으로 갔다. 하나의 경로에 전부 걸지 않는 게 요점이다.

xcancel·Nitter류 미러는 서비스가 불안정해 다루지 않았고, 브라우저 세션 로그인 방식도 시도하지 않았다. 계정 잠금 리스크가 있는 경로는 이번 검증 범위 밖이다.
